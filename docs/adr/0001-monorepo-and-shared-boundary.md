# ADR-0001：monorepo 结构与共享层准入

> **状态：已被 [ADR-0003](0003-shared-by-copy.md) 取代（2026-10-20，BING-47）。**
> `apps/*` 与 `packages/*` 已删除；共享改为「复制 + 版本戳」。本文保留作为决策历史。

- **背景**：blurface 的 P0/P1 验证了「单用途工具站 + 共享编辑器内核」的模式，第二、第三个工具页要复用同一引擎；共享代码散在各仓库会让每页的边际成本回到从零开始。
- **选择**：pnpm monorepo，`apps/*` 放站点、`packages/*` 放共享包；v1 只建三个包——`editor-core`（已有 3 个真实使用方）、`seo-kit`（每站都要用）、`site-template`（新站复制即起）。不建 `core`/`utils` 这类无明确使用方的桶包。
- **代价**：跨仓消费仍靠手工同步一次（blurface 在本仓库外部署），下次重建该站时整体迁入 `apps/` 消除双份代码。回看时机：第二个站点上线后。

# ADR-0002：共享层接口即契约，站点差异走配置

- **背景**：`editor-core` 从已上线的 blurface 代码原样抽包，三个工具页（照片打码 / 车牌 / 像素化）依赖同一组接口。
- **选择**：接口保持不变（`EditorEngine` / `detectFaces` / `renderComposition`）；站点差异只允许两种表达——调用参数（效果强度、preset）与 `configureFaceDetection` 这类路径配置；不在包里加 `if (site === "...")` 分支。
- **代价**：站点若需要包内不支持的能力，先在站点内组合实现；第二个站点也需要时才回包内加，并按「列全部使用方影响」流程改。
